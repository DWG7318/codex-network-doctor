# CND-CASE-2026-001：v2rayN TUN 因 Windows 排除端口范围无法启动

状态：已解决
日期：2026-07-30
适用：Windows 10/11、v2rayN 7.x、sing-box TUN
关键词：v2rayN、TUN、sing-box、WSAEACCES、10013、excluded port range、external controller

## 脱敏声明

本记录由一次真实故障处置过程整理而成。下列信息在入库前已删除或替换：

- Windows 用户名、计算机名和个人目录；
- 代理节点名称、服务器公网 IP、订阅信息和认证材料；
- 原始本地端口、进程号、请求 ID、时间戳和 Cookie；
- 微信目录、聊天附件路径、截图和诊断包哈希。

文中的 `<V2RAYN_ROOT>`、`<BASE_PORT>`、`<CONTROL_PORT>`、`<SAFE_BASE_PORT>` 和
`<BACKUP_PATH>` 均为占位符，不对应原设备上的实际值。

## 用户可见现象

- 微信可以联网，浏览器和 Codex 无法联网。
- v2rayN 节点本身可用，并且用户需要开启 TUN。
- 打开 TUN 后，`singbox_tun` 网卡没有稳定出现。
- Windows 系统代理曾指向一个没有监听者的本机地址。

## 完整脱敏处置日志

### T+00：采集和边界确认

1. 确认 v2rayN GUI 位于 `<V2RAYN_ROOT>`，节点配置存在。
2. 确认没有存活的 sing-box/xray 核心，没有已启动的 `singbox_tun` 网卡。
3. 发现 Windows 用户代理仍指向 `127.0.0.1:<STALE_PROXY_PORT>`，但该端口没有监听者。
4. 诊断包只用于判断本机状态；真实包没有进入案例库或源码仓库。

### T+01：清除失效代理并校正 TUN 核心

1. 备份 `guiConfigs/guiNConfig.json` 到 `<BACKUP_PATH>`。
2. 清除失效的 WinINet/WinHTTP 代理状态。
3. 确保 `TunModeItem.EnableTun=true`。
4. 对当前 Shadowsocks 配置使用 v2rayN 的 sing-box 核心，以便生成 TUN 配置。
5. 停止同一安装目录中的重复 v2rayN GUI 和遗留核心，然后重新启动保留实例。

结果：v2rayN 可以生成 sing-box 配置，但核心立即退出。

### T+02：定位第二层故障

脱敏后的核心错误为：

```text
FATAL start service:
external controller listen error:
listen tcp 127.0.0.1:<CONTROL_PORT>:
bind: An attempt was made to access a socket in a way forbidden by its access permissions.
```

检查监听表后，没有发现占用 `<CONTROL_PORT>` 的普通进程。错误属于 Windows
`WSAEACCES/10013`，而不是常见的“端口已被其他进程监听”。

随后检查 Windows IPv4/IPv6、TCP/UDP 的 excluded port range，确认
`<CONTROL_PORT>` 位于系统保留区间。v2rayN 的控制端口由基础端口派生，因此仅重启
GUI、强制结束进程或反复开关 TUN 都不会消除冲突。

### T+03：迁移到安全端口块

1. 停止 `<V2RAYN_ROOT>` 内的 v2rayN GUI 和已知代理核心。
2. 枚举 Windows TCP/UDP 排除端口范围与当前监听端口。
3. 在高位端口区间寻找连续 32 个未被排除、未被监听的端口。
4. 将 `Inbound[0].LocalPort` 从 `<BASE_PORT>` 改为 `<SAFE_BASE_PORT>`。
5. 保留原配置备份，并使用临时文件加原子替换写回配置。
6. 重新启动 v2rayN；若 GUI 未拉起核心，则使用其生成的配置直接启动 sing-box，
   同时把 stdout/stderr 写入本地故障日志。

### T+04：验证

验证结果：

- sing-box 核心保持运行；
- `singbox_tun` 网卡状态为 Up；
- 新的 Mixed/控制端口开始监听；
- 绕过显式系统代理直接请求 OpenAI HTTPS，收到 HTTP 401；
- 浏览器和 Codex 恢复联网。

未携带 API Key 请求 `/v1/models` 时，HTTP 401 表明 DNS、路由、TCP、TLS 和 HTTP
链路均已通过；它不是本次网络修复失败。

## 根因

直接根因：v2rayN 派生出的 sing-box external controller 端口落入 Windows excluded
port range，核心绑定回环地址时返回 WSAEACCES/10013，导致 TUN 核心退出。

伴随条件：

- 遗留的失效系统代理放大了“部分软件可联网、浏览器不可联网”的表象；
- Shadowsocks 的核心映射需要与 v2rayN TUN 所使用的 sing-box 保持一致；
- 只检查进程监听表不足以识别 Windows 保留端口冲突。

## 程序化处置规则

1. 修改前必须备份 `guiNConfig.json`。
2. 只终止明确属于同一 v2rayN 安装目录的 GUI 和已知核心；不得终止未知端口占用者。
3. 同时检查 IPv4/IPv6 与 TCP/UDP excluded port range。
4. 新基础端口应来自连续安全端口块，而不是只验证单个端口。
5. 配置更新后必须验证核心、TUN 网卡和不使用显式代理的 HTTPS。
6. 验证失败时保留日志并允许从备份撤销。
